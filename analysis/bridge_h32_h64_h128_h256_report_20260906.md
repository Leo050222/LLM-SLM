# 32/64/128/256-token bridge rollout 对比分析

## 数据口径与完整性

- 原 prefix：13,244 条，每条 8 次 rollout，共 105,952 次。
- 每个 bridge horizon：8 个生成重复，每个重复 105,952 次 rollout，合计 847,616 次。
- 每个 horizon 有 `13,244 prefixes × 8 source bridges = 105,952` 个 bridge 组；每个 `(prefix, bridge)` 的正确率由 8 个生成重复估计。
- 提升档位相对原 prefix 的 8 次 rollout 计算，范围 −100 到 +100 pp，步长 12.5 pp。
- 整体 trace = response prefix + bridge + Student continuation。
- trace 缩短量 = 原 prefix 整体 trace 均值 − 接 bridge 后整体 trace 均值，正值表示变短。
- `clean` 统计排除对比任一侧出现 `finish_reason=length` 的 bridge 组。
- 128-token 的 8 个 merged score 文件全部存在；分析器验证了 `(dataset_index, rollout_index)` 无重复且覆盖精确完整。

128-token 的新增结果：

- 正确率 42.0167%，比原 prefix 高 2.7498 pp，比 64-token 高 1.0156 pp，比 256-token 低 2.1898 pp。
- continuation 平均缩短 128.66 tokens；加上 128-token bridge 后，整体 trace 平均仍比原 prefix 短 0.66 token，基本处于长度盈亏平衡点。
- 单位 bridge token 收益为 0.0215 pp/token；32/64/128/256 依次为 0.0385、0.0271、0.0215、0.0193 pp/token，边际收益持续递减。
- `length finish` 从 64-token 的 84 增至 128-token 的 190，但仍远低于 256-token 的 1,083。

## 5. +100 pp bridge 的 prefix 集中度

`+100 pp` 严格表示原 prefix 的 8 次 rollout 全错，而当前 `(prefix, bridge)` 下的 8 个生成重复全对。

| Bridge | +100 pp bridge | 涉及 prefix | 每个涉及 prefix 平均个数 | 来自含多个 +100 pp 的 prefix | 涉及 prefix 中含 ≥2 个的占比 | 8 个 bridge 全部 +100 pp |
|---:|---:|---:|---:|---:|---:|---:|
| 32 | 157 | 37 | 4.24 | 152 / 157 = 96.82% | 32 / 37 = 86.49% | 6 prefixes / 48 bridges |
| 64 | 214 | 68 | 3.15 | 184 / 214 = 85.98% | 38 / 68 = 55.88% | 6 / 48 |
| **128** | **344** | **131** | **2.63** | **278 / 344 = 80.81%** | **65 / 131 = 49.62%** | **12 / 96** |
| 256 | 731 | 275 | 2.66 | 614 / 731 = 83.99% | 158 / 275 = 57.45% | 17 / 136 |

128-token 的 +100 pp bridge 覆盖了 131 个 prefix，是 64-token 的近两倍；其集中度最低，说明新增的完美恢复更多来自扩展到新的 prefix，而不是只在少数容易被 bridge 救回的 prefix 上重复出现。

## 6. 结论与建议实验

1. **绝对正确率随 bridge 长度单调提高**：39.27% → 40.50% → 41.00% → 42.02% → 44.21%。
2. **128-token 是整体 trace 的平衡点**：continuation 的缩短几乎恰好抵消 128-token bridge，整体长度与原 prefix 基本相同，同时得到 +2.75 pp。
3. **单位 token 效率递减**：短 bridge 更高效，长 bridge 提供更高绝对正确率。
4. **长度变化与提升弱正相关**，但不足以支持因果解释。下一步应做 prefix-cluster bootstrap，以及带 prefix 固定效应的 `lift ~ trace_reduction + horizon + baseline_difficulty` 回归。
5. 若还要补点，建议优先测试 96 和 192 tokens，以定位整体 trace 从持平转为增长的拐点及正确率边际收益曲线。
