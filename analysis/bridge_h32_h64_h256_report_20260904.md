# 32/64/256-token bridge rollout 对比分析

## 口径与数据完整性

- 原 prefix：13,244 条，每条 8 次 rollout，共 105,952 次。
- 每个 bridge horizon：8 个生成重复；每个重复 105,952 次 rollout，合计 847,616 次。
- Bridge 级样本：`13,244 prefixes × 8 source bridges = 105,952`。每个 `(prefix, bridge)` 的正确率由 8 个生成重复估计。
- 提升档位：相对原 prefix 的 8 次 rollout，范围为 −100 到 +100 pp，步长 12.5 pp。
- 整体 trace：response prefix + bridge + Student continuation。
- trace 缩短量：原 prefix 续写的整体 trace 均值减去接 bridge 后的整体 trace 均值；正值表示接 bridge 后更短。
- `clean` 统计排除了对比任一侧出现 `finish_reason=length` 的 bridge 组。
- 32/64-token 的正式 merged score 尚未全部生成，但 64 个 score shards 均完整；分析器对 `(dataset_index, rollout_index)` 做了去重和精确覆盖校验后直接读取分片。

主要观察：

- 32-token 已带来 +1.23 pp；64-token 为 +1.73 pp，比 32-token 再高 +0.50 pp；256-token 总提升最大，为 +4.94 pp。
- 按每个 bridge token 的正确率收益计算，32/64/256 分别约为 0.0385、0.0271、0.0193 pp/token，呈边际收益递减。
- 32/64-token 不仅 continuation 更短，连包含 bridge 的整体 trace 均值也分别缩短 6.45/7.34 tokens。256-token continuation 大幅缩短 204.35 tokens，但不足以抵消更长 bridge，整体 trace 均值增加 51.65 tokens。

|---:|---:|---:|---:|---:|---:|---:|

结论：三个 horizon 都是正相关，而且提升档位越高时，平均 trace 缩短量总体越大；但相关系数只有约 0.07–0.13，属于弱相关。也就是说，trace 变短是一个有信息的伴随现象，但远不足以单独解释 bridge 的正确率提升。

## 5. +100 pp bridge 的 prefix 集中度

这里的 +100 pp 严格表示：原 prefix 的 8 次 rollout 全错，而在当前 `(prefix, bridge)` 下 8 个生成重复全对。

| Bridge | +100 pp bridge 数 | 涉及 prefix 数 | 每个涉及 prefix 平均个数 | 来自有多个 +100 pp bridge 的 prefix | 涉及 prefix 中含 ≥2 个的占比 | 8 个 bridge 全部 +100 pp 的 prefix |
|---:|---:|---:|---:|---:|---:|---:|
| 32 | 157 | 37 | 4.24 | 152 / 157 = 96.82% | 32 / 37 = 86.49% | 6（贡献 48 个 bridge） |
| 64 | 214 | 68 | 3.15 | 184 / 214 = 85.98% | 38 / 68 = 55.88% | 6（贡献 48 个 bridge） |
| 256 | 731 | 275 | 2.66 | 614 / 731 = 83.99% | 158 / 275 = 57.45% | 17（贡献 136 个 bridge） |

32-token 的 +100 pp 数量最少，但集中度最高：一旦某个 prefix 出现一个 +100 pp bridge，它往往还会有其他 bridge 同样达到 +100 pp。64/256 覆盖到更多不同 prefix，分布更广。

## 6. 判断与后续实验

1. 如果目标是单位 teacher token 的收益，32-token 最有效；如果目标是绝对正确率，256-token 最好。
2. 64-token 相比 32-token 只增加 +0.50 pp，但 continuation 再缩短约 32.9 tokens；它是当前准确率、长度与成本之间较平衡的点。
3. “trace 变短导致正确率提升”目前不能作为因果结论。建议下一步做 prefix-cluster bootstrap，并用 prefix 固定效应回归 `lift ~ trace_reduction + horizon + baseline_difficulty`。
4. 建议补 16/96/128-token，以更清楚定位边际收益曲线；尤其 64 到 256 之间跨度过大。
